--- ARQUIVO 3: script.js ---

**Este é o arquivo mais importante para a apresentação.** Todo o funcionamento do
sistema está aqui. Código organizado em linhas separadas, sem comentários // no
início de linhas (conforme exigido pelo edital).

Estrutura do script.js (organizada, sem // no início de linha):

1. CONSTANTES NO TOPO:
   - STORAGE_KEY: 'hrmasters_funcionarios' (chave para salvar no navegador)
   - DEPARTMENTS_KEY: 'hrmasters_departamentos' (chave para departamentos)
   - funcionariosIniciais: array com 3 funcionários já cadastrados (Mariana, Lucas, Camila)
   - departamentosIniciais: array com 4 departamentos (RH, Financeiro, Tecnologia, Administrativo)

2. FUNÇÕES PRINCIPAIS:

   A) getFuncionarios()
      - Pega dados do localStorage do navegador
      - Se houver dados salvos, converte JSON de volta para array JavaScript
      - Se não houver dados, usa os funcionariosIniciais (3 já cadastrados)
      - Isso garante que sempre tenha dados para exibir

   B) saveFuncionarios(funcionarios)
      - Salva o array de funcionários no localStorage
      - Converte array JavaScript para texto JSON (JSON.stringify)
      - Dados persistem mesmo após fechar o navegador e reabri-lo
      - Essa é a "base de dados" do sistema (sem backend)

   C) gerarId()
      - Gera IDs únicos para novos funcionários
      - Usa .reduce() para encontrar o maior ID existente
      - Retorna maxId + 1 (próximo ID disponível)
      - Evita IDs repetidos

   D) getDepartamentos()
      - Funcionamento idêntico a getFuncionarios(), mas para departamentos

   D) saveDepartamentos(departamentos)
      - Funcionamento idêntico a saveFuncionarios(), mas para departamentos

   E) renderFuncionarios(filtrados = null)
      - **Função mais importante** - desenha a tabela de funcionários
      - Se receber uma lista filtrada, usa ela; senão, pega todos
      - Limpa a tabela e cria linhas dinamicamente com document.createElement('tr')
      - Cada linha tem: foto/iniciais do nome, cargo, departamento, data admissão,
        badge de status (ativo/inativo com cores), botões Editar e Excluir
      - Cada botão tem data-id="id_do_funcionario" para identificar qual clicar
      - Chama atualizarIndicadores() ao final para atualizar o dashboard

   F) atualizarIndicadores()
      - Atualiza os números no dashboard (total/ativos/inativos)
      - Conta funcs.length para total
      - Usa .filter(f => f.status === 'ativo') para contar ativos
      - Usa .filter(f => f.status === 'inativo') para contar inativos
      - Atualiza elementos .stat-number no HTML com os novos valores

3. EVENT LISTENERS - Quando a página carrega (DOMContentLoaded):

   A) Renderizar ao carregar:
      - Chama renderFuncionarios() assim o HTML terminar de carregar

   B) Formulário de cadastro:
      - Evento: form.addEventListener('submit', function(e) { e.preventDefault(); ... })
      - e.preventDefault() impede que a página recarregue
      - Captura valores de todos os campos: form.nome.value, form.cpf.value, etc.
      - Validação: se nome, cpf ou email vazios, mostra alert() e para
      - Cria objeto novoFuncionario com todos os dados + id: gerarId() + dataCriacao: new Date().toISOString()
      - Pega array atual com getFuncionarios(), adiciona novo com .push(), salva com saveFuncionarios()
      - Re-exibe tabela e limpa formulário com .reset()

   C) Filtro de busca em tempo real:
      - Evento: buscaInput.addEventListener('input', function(e) { ... })
      - Detecta cada tecla pressionada no input de busca (no topo da página)
      - termo = e.target.value.toLowerCase() (busca case-insensitive)
      - .filter(f => f.nome.toLowerCase().includes(termo) || f.cargo.toLowerCase().includes(termo) || f.departamento.toLowerCase().includes(termo))
      - Cria array apenas com funcionários que matcham a busca
      - Re-exibe tabela mostrando apenas os matching

   D) Botões Editar/Excluir (Event Delegation):
      - Evento: document.querySelector('#funcionarios-table').addEventListener('click', function(e) { ... })
      - Captura click na tabela inteira ao invés de adicionar listener em cada botão
      - id = parseInt(e.target.dataset.id) (pega o ID do botão clicado)
      - Excluir:
        * if (e.target.classList.contains('btn-excluir'))
        * confirm('Tem certeza que deseja excluir este funcionário?')
        * .filter(f => f.id !== id) remove o item da array
        * saveFuncionarios() salva a nova array
        * renderFuncionarios() atualiza a tabela
      - Editar:
        * if (e.target.classList.contains('btn-editar'))
        * .find(f => f.id === id) encontra o funcionário com aquele ID
        * Preenche todos os campos do formulário com os dados atuais: form.nome.value = func.nome, etc.
        * form.onsubmit = function(e) { ... } define o que acontece ao submeter após editar
        * Remove antigo com .filter(), cria objeto atualizado com dados do formulário, salva, re-renderiza
        * form.onsubmit = null (handler "one-time" - só funciona uma vez, depois é removido)

--- RESUMO PARA A APRESENTAÇÃO ---

O que o professor pode perguntar (3 perguntas, 1 ponto cada = 3,0 pontos):

1. LOCALSTORAGE:
   - "Explique como esta função salva os dados e por que usamos JSON."
   - Resposta: localStorage salva no navegador, JSON.stringify converte objeto para texto,
     JSON.parse converte texto de volta. Chave STORAGE_KEY organiza os dados.

2. FILTRO DE BUSCA:
   - "Explique como o filtro em tempo real funciona enquanto o usuário digita."
   - Resposta: addEventListener('input') detecta cada tecla, toLowerCase() faz busca
     case-insensitive, filter() cria novo array com apenas os que matcham, renderFuncionarios()
     re-exibe a tabela.

3. CRUD - EDITAR/EXCLUIR:
   - "Explique o mecanismo de editar e excluir um funcionário, especialmente o uso de event delegation."
   - Resposta: Event delegation = capturar click na tabela ao invés de em cada botão.
     data-id no HTML identifica qual func. confirm() é a caixa de diálogo. .filter(f => f.id !== id)
     remove o item. form.onsubmit = null evita que funcione duas vezes.
